# Inventory, Hold, Checkout, and Payment State Machines

**Status:** Specified — Not Executed — Not Verified

## `STATE-INV-001` — Inventory movement

Each transition appends a movement (`received`, `adjusted`, `held`, `released`, `sold`, `returned`, `damaged`, `transferred`) after ownership and non-negative-balance guard. `EVT-STOCK-MOVED` updates projections. Invalid/concurrent request fails without a movement; recovery is a compensating movement, never an edited balance.

| From → to                                          | Actor                                      | Guard                                                                                 | Side effect                                               | Timeout/terminal/recovery                                                           |
| -------------------------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------- | --------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Available → Held                                   | Checkout                                   | scoped SKU-variant/Location, requested quantity available, new/matching hold identity | append `held` movement and reserve quantity               | hold expiry is governed by `STATE-CHK-001` and releases once                        |
| Held → Available                                   | expiry worker/Checkout                     | active uncommitted hold or approved release                                           | append `released` movement, emit availability event       | duplicate release is a no-op; new quote is required                                 |
| Held → Sold                                        | Checkout                                   | one valid committed Purchase component                                                | append `sold` movement and preserve hold/Purchase link    | terminal for committed quantity; later correction is a new return/refund path       |
| Sold → Returned                                    | authorized aftercare flow                  | accepted ReturnCase and received/disposition evidence                                 | append `returned` or `damaged` movement; emit audit event | refund/provider uncertainty reconciles without altering movement                    |
| Any counted balance → Adjusted/Damaged/Transferred | scoped Vendor/Platform inventory authority | reason/evidence and non-negative result; high-risk approval where policy requires     | append immutable movement and audit/event                 | failed validation changes nothing; correction appends another compensating movement |

## `STATE-CHK-001` — CheckoutHold

| From → to                         | Actor                    | Guard                                                                   | Side effect                                                              | Timeout/terminal/recovery            |
| --------------------------------- | ------------------------ | ----------------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------ |
| Quote → Holding                   | Customer/Checkout        | verified Customer, current price/eligibility, all stock+Staff allocable | append hold/stock reservation and booking allocation, `EVT-HOLD-CREATED` | conflict returns unavailable/requote |
| Holding → AwaitingPayment         | Checkout                 | all components held; idempotency key new/replay matches                 | provider intent request/outbox                                           | 15-minute expiry starts              |
| AwaitingPayment → Committed       | verified provider result | valid unexpired hold and exact payment link                             | create Purchase/Orders/Bookings, ledger/outbox                           | terminal commercial commit           |
| Holding/AwaitingPayment → Expired | clock worker             | expiry reached without valid commit                                     | release all components/events                                            | retry starts fresh quote             |
| Expired → Compensating            | verified late success    | provider success after expiry                                           | refund/reversal/reconcile                                                | terminal refunded/exception case     |

## `STATE-PAY-001` — Payment attempt

| From → to                              | Actor                                             | Guard                                                                            | Side effect                                                                    | Timeout/terminal/recovery                                                          |
| -------------------------------------- | ------------------------------------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| Created → PendingProvider              | Checkout/provider adapter                         | valid CheckoutHold, matching idempotency identity, no prior semantic result      | create provider operation through outbox and persist attempt reference         | provider timeout leaves attempt pending/unknown, never committed by browser result |
| PendingProvider → Succeeded            | verified provider callback/reconciler             | signature/inbox/reference/environment/amount match and unexpired commercial path | persist verified result; command `STATE-CHK-001` commitment and ledger posting | terminal payment success; duplicate callback returns prior result                  |
| PendingProvider → Failed               | verified provider callback/reconciler             | authoritative final failure for matching attempt                                 | persist safe failure and release/requote path                                  | terminal failure; Customer may begin a new attempt                                 |
| PendingProvider → Unknown              | timeout/reconciler                                | no authoritative final provider result by target retry window                    | create reconciliation work and retain all references                           | no Purchase/earning inference; retry fetch/reconciliation                          |
| Unknown → Succeeded/Failed             | reconciler                                        | later authoritative provider result is verified                                  | apply the matching success/failure transition once                             | if hold expired on late success, invoke checkout compensation/refund               |
| Succeeded → Refunded/PartiallyRefunded | authorized refund flow + verified provider result | eligible scoped component/case and approved amount                               | append reversal/compensating posting and outcome event                         | provider uncertainty returns to reconciliation; original success is never edited   |
