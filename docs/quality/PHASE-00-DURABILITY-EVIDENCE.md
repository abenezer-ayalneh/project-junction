# Phase 00 durability evidence — 2026-09-21

Status: local synthetic foundation implemented; full Phase 00 acceptance remains open.

## Scope and reproduction

This evidence concerns the Phase 00 continuation of the in-memory prototype. PostgreSQL 18/PostGIS runs in the project Compose service on loopback port 55432. The image requires AMD64 emulation on this ARM Mac. No external provider, real identity, public deployment, or commerce is involved. No Git repository/commit exists in this workspace.

Use Node 24 and pnpm 10.32.1. Install dependencies with `pnpm install`, then run:

```sh
pnpm env:local:up
# Create .env from .env.example only if no local .env already exists.
# Export its local settings into the current shell without printing them.
set -a
. ./.env
set +a
pnpm db:generate
pnpm db:migrate:local
pnpm db:compat:check
pnpm check
pnpm test:integration
pnpm dev
```

`FOUNDATION_STORAGE=postgresql` selects durable synthetic storage and requires `DATABASE_URL`. Without that mode, existing unit-test doubles remain available and health labels them accordingly. Durable mode never seeds the prototype's fixed session. Tests create scoped, short-lived synthetic sessions explicitly. `SYNTHETIC_WEBHOOK_WORKSPACE_ID` must identify a synthetic workspace before the fake callback route is accepted. `SYNTHETIC_WEBHOOK_SECRET` supplies the local HMAC key; this adapter is not provider-specific signature verification.

`db:compat:check` applies the migration history to a uniquely named disposable schema, then compares that exact database schema with `prisma/schema.prisma`. It drops only that generated schema in `finally`. `db:restore:check` verifies that `DATABASE_URL` is the configured loopback Compose PostgreSQL port, creates a separately generated schema, migrates and seeds it, takes a custom-format `pg_dump` inside the PostgreSQL container, drops only that generated schema, restores it with `pg_restore`, verifies the persisted fixture counts and per-persona quota fields, then removes both the restored generated schema and the container-local temporary dump in `finally`. `test:integration` runs these checks through Nx after applying the migration chain twice, then executes PostgreSQL tests and the cross-process smoke in a separate uniquely named schema. Use the project's synthetic database. It requires schema/extension creation privileges. No shared schema is reset or truncated. Logs must not contain environment values, tokens, or provider payloads.

## Persistence and audited SQL lane

`libs/platform-core/src/lib/postgres-foundation.ts` owns the prototype persistence boundary. Public contracts do not import generated Prisma types. The client is generated under `libs/platform-core/generated/prisma`; Nx generation precedes builds/typechecks. API builds keep this library external so generated runtime assets resolve at their package location.

Raw SQL is limited to parameterized identity/workspace locks, provider/quota advisory locks, and outbox claim/recovery. Prisma handles CRUD. Workspace row locks serialize commands and purge within one workspace; this is deliberately conservative. `db:lock:measure`, run by the integration target against its generated schema, issues 16 distinct concurrent foundation writes through that exact path, verifies 16 audit/outbox records, and reports elapsed, p50, and p95 latency. It is a reproducible local baseline, not a production capacity limit or load certification. Session, User and membership locks prevent revocation racing an accepted command. Provider identity has a transaction-level advisory lock plus a unique constraint. Hash collisions serialize unrelated callbacks but cannot bypass unique identity checks.

Outbox selection uses `FOR UPDATE SKIP LOCKED`; claims have fresh fencing tokens, a 30-second lease and a three-attempt budget. Failures back off exponentially. Expired final attempts move to `dead_letter`; operators can inspect durable state. Completion atomically writes a unique synthetic receipt and acknowledges the claim. A stale worker cannot acknowledge a reclaimed token, including when the worker name is reused. This demonstrates database-only consumer effects; external side effects still need their own idempotent adapter.

The additive migration stream retains prior columns while expanding Session, IdempotencyRecord, ProviderInboxEvent and OutboxEvent, and adding OutboxReceipt, DemoPersona and reconciliation metadata. It performs no data backfill or destructive contraction. Roll back application code while retaining the added schema; do not drop columns or erase the database to undo a deployment. The migration lockfile and `db:compat:check` verify migration/schema alignment in a fresh disposable schema. `db:upgrade:check` seeds User, Workspace, Vendor, Location, Session and ProviderInboxEvent rows through the original migration, applies every later migration, and verifies those rows plus additive defaults. `db:rollback:check` creates a temporary worktree at the prior Phase 00 foundation commit, builds its platform-core library using the current dependency installation, and proves that compiled older access derivation and idempotent command writes work against a generated schema at the current migration head. It removes the worktree and only its scoped fixture data in `finally`. This is a bounded application-code rollback probe, not a deployment rollback or a promise that arbitrary historical artifacts remain supported.

The API builds its OpenAPI 3.0 components from the public Zod schemas. `apps/api/src/app/swagger.spec.ts` snapshots the complete v1 document, including routes, required headers, request/response references, and the session security scheme; any contract change fails the API test until the baseline is explicitly reviewed and updated. The gate also rejects persistence and provider-secret identifiers in the generated document. Every HTTP response carries `X-Request-Id`; a valid client UUID is preserved, otherwise a server UUID is generated, and health/error bodies carry the same value. Every `/v1` response also carries browser-readable `X-API-Version: v1` and `X-API-Lifecycle: active`; the API conventions specify replacement/sunset requirements before an endpoint can become deprecated. This records a local synthetic contract baseline, not a public compatibility promise.

Demo workspaces have their own persisted `DemoPersona` actors rather than borrowing a real `User`. Creation is unauthenticated only for a new synthetic fixture; it returns one Vendor Owner session and the safe persona list. A switch requires that current demo session, revokes it in the same transaction, records `demo.persona-switched`, and issues a fresh session for exactly one persona. Redis-backed API nodes immediately disconnect any sockets for the superseded session. Only the Vendor Owner fixture receives the synthetic Vendor/Location scope and foundation write capability. Workspace expiry is checked before every derivation. Demo purge removes workspace sessions, personas, memberships, locations, vendors, idempotency, inbox, outbox, receipts and audit records. A minimal workspace/expiry tombstone remains. Demo creation/switch now set a scoped HttpOnly, SameSite=Lax, HMAC-signed cookie; REST and Socket.IO reverify it before deriving scope. The local `x-junction-session` header remains a developer/test transport, while full cross-store identity lifecycle remains open.

The only current demo provider substitute is the fake payment callback. Each live demo workspace starts with a durable 25-event allowance. A unique callback consumes one allowance under the workspace transaction; an exact duplicate is acknowledged before quota consumption, and a new callback after exhaustion is denied. Each persisted demo persona separately has a durable 25-command allowance for the implemented foundation write seam; the transaction checks idempotency first, then increments only that persona's counter before the audit/outbox/idempotency write. This does not claim quotas for media, jobs, or storage because no such Phase 00 stores/actions are implemented.

The separate elevated audit-marker route is the local privileged-mutation seam. It calls the same server-derived context path but permits only a real Vendor Owner with a present, non-future MFA timestamp and recent authentication no older than 15 minutes; demo personas cannot use it. It proves the policy guard without claiming that a complete production identity or MFA enrollment system exists.

Durable Users now carry an additive adult-verification lifecycle state. A legacy verified timestamp upgrades to `verified`; during the documented mixed-version compatibility window, an older writer that omits the lifecycle field receives `legacy_verified_compat` and derives only when it supplied a verified timestamp. Current writers must set an explicit lifecycle state; explicit `unverified`, `pending`, or `rejected` state cannot derive a session even if a timestamp is present. The local proof covers persisted state transitions and session denial, not a document-verification provider, self-service account flow, or public browsing.

An optional `Staff` profile can link to a User and one Vendor. A linked VendorMembership is accepted only when the Staff profile still names the same User and Vendor; an altered link safely denies the existing session. The local fixture lifecycle provisions only `@example.invalid` accounts behind a server-held secret; its `verified` state is an operator-selected synthetic test fixture, not real identity evidence. An active real synthetic Vendor Owner may grant that verified fixture a valid-location-scoped Staff membership and one-hour session. Revoking it atomically deletes the Staff/membership binding, revokes matching active Staff sessions, records an audit event, and tells every local realtime gateway to disconnect those sessions. This is a foundation identity binding, not real authentication, identity verification, or a complete personnel lifecycle.

Public browsing is intentionally limited to `GET /v1/public/vendors`. It returns only an explicitly published, non-demo Vendor ID and slug, applies a typed cursor/limit contract, and never returns workspace, Location, User, or membership information. It is not a public catalog, search, or market release.

The local Socket.IO gateway accepts only forced-WebSocket connections whose session derives successfully. On every `room.join`, it derives the context again and accepts only the current workspace, active Vendor, or permitted Location. A failed recheck leaves all scoped rooms and returns a generic denial. An authorized durable join returns the current workspace outbox high-water cursor and, for a known cursor, up to 25 ordered redacted durable events. An unknown or over-limit cursor returns no events with the explicit REST-refetch signal. With explicit `REALTIME_REDIS_FANOUT=enabled` and a valid Redis URL, paired API processes share a Socket.IO Redis adapter. A newly accepted foundation command emits its durable event ID, cursor, time, workspace scope, and empty payload; before each matching local or remote socket receives it, the server re-derives that socket's session and removes the workspace room if authority no longer agrees. Failure to configure or use fanout cannot change a command outcome; REST remains authoritative. This local proof covers only workspace notifications, not projection delivery.

The fake payment callback contract is intentionally small: a callback names a provider reference and either `timed_out` or `confirmed`. Nest passes its raw request body to a provider-neutral webhook adapter port; the local `FakePayment` implementation owns the `sha256=` HMAC check with `SYNTHETIC_WEBHOOK_SECRET`, normalizes the inbound event, and fails closed before the generic inbox/reconciliation path. A timeout is durably retained as `pending_reconciliation`; a separate confirmed event for that same reference atomically settles pending timeout records and emits one reconciliation event. The adapter is deliberately deterministic and local-only, not a real provider-specific integration or authenticated provider truth; real adapters and external-effect idempotency remain open.
