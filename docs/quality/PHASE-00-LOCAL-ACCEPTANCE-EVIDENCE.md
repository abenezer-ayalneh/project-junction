The realtime check used an authenticated local Socket.IO client and exercised the actual API gateway:

1. It joined the workspace room, acknowledged its empty baseline cursor, and disconnected.
2. While disconnected, the local reviewer published the disposable listing.
3. On reconnect, server-owned replay included `ListingPublished`.

This proves the local PostgreSQL outbox → worker → Redis stream/live notification → authenticated replay/acknowledgement path. It does not prove any remote ingress or provider behavior.

This enforces the existing decision; it introduces no new authentication policy.

The full `pnpm nx run platform-core:test-integration --skipNxCache` run also passed all 43 Jest integration tests, the Google callback probe, the separate Better Auth MFA probe, migration compatibility/populated upgrade, local restore rehearsal, and lock measurement. Seven retained identity/MFA cases now explicitly select strict policy and seed matching Better Auth rows instead of inheriting the local relaxation. Other fixtures explicitly use local policy. Both profiles run only against loopback PostgreSQL. The runner removes authentication identities belonging to its disposable domain schema before dropping the schema; nine orphaned fixture identities from this follow-up’s earlier failed runs were removed separately, excluding active application accounts.

Platform-core unit tests passed all 18 cases; typechecking, focused auth-file lint, and the two test-tool lint checks passed. Whole platform-core lint retains six existing errors in email-delivery and media/integration test code; no whole-project lint pass is claimed. Documentation audit and whitespace checks passed.
