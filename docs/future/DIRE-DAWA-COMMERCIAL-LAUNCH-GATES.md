# Dire Dawa Commercial Launch Gates

**Status:** Unapproved — Requires future validation  
**Decision coverage:** `DEC-001`, `DEC-011`, `DEC-025`, `DEC-066`, `DEC-077`, `DEC-109`, `DEC-120`, `DEC-153`

No commercial launch, real payment, Vendor recruitment, customer account collection, or real identity verification is authorized until all gates have dated evidence and explicit approval.

| Gate                         | Required decision-quality evidence                                                         | No-go condition                                |
| ---------------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------- |
| Market and Vendor demand     | representative research, demand/supply hypothesis, consented feedback                      | reliance on synthetic portfolio content        |
| Legal/privacy/tax            | qualified validation for entity, marketplace role, privacy, consumer rights, tax/invoicing | assumptions or generic web summaries           |
| Payments/KYB                 | permitted merchant/seller/settlement model, provider contracts and sandbox-to-live path    | Stripe sandbox demonstration only              |
| Logistics/service operations | pickup/delivery responsibility, address safety, incident/support capacity                  | unpriced or unowned operating obligations      |
| Economics                    | cost, fee, refund, fraud, support, and Vendor earnings model with sensitivity analysis     | unexplained subsidy or negative unit economics |
| Security/reliability         | implementation evidence, ASVS review, restore drill, incident response                     | documents without executed proof               |
| Pilot                        | bounded cohort, consent, success/failure metrics, stop conditions                          | open-ended public release                      |

The go/no-go record must identify approvers, evidence dates, remaining risk, legal limitations, customer remediation plan, and data/environment boundary. Passing one gate does not waive another.
