# Implemented resource-ID boundary inventory — local synthetic runtime

**Status:** Partially verified, 2026-09-23. This inventory covers implemented HTTP routes, Socket.IO messages, and their `PostgresFoundation` entry points. A session ID is a transport credential, never a scope claim. `derive` rechecks the session, adult state, workspace, active role, Vendor membership, Staff binding, assigned Location IDs, and demo expiry under a workspace transaction lock. Restricted or rejected Vendors no longer derive a Vendor session. "Owner" below means a current `vendor_owner` membership for the active Vendor, including the scoped demo owner unless a real User is explicitly required. Platform review means a current `trust` or `platform_owner` demo persona in the target workspace. The local runtime has no general platform account or assigned-case model.

The current schema has no Location-scoped listing mutation, signed-media URL, listing deletion, or client-addressable job replay endpoint. These `TST-SEC-012` parts remain open. The adversarial PostgreSQL fixture exercises two workspaces and multiple Vendors with real foreign IDs; the built API smoke exercises foreign HTTP IDs and Socket.IO room IDs. The existing demo/customer and worker suites cover their other implemented boundaries. This inventory is not a claim that every specified future capability exists.
