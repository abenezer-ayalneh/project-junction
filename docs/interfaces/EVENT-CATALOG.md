Events carry immutable event ID, aggregate ID/version, causation/correlation/idempotency IDs, time, schema version, environment/workspace scope, producer, and minimal safe payload. Transactional outbox ensures committed source state; consumer inbox/dedup/retry/dead-letter/replay handles delivery. Ordering is guaranteed only per aggregate/source sequence; consumers reconcile from REST/source truth after gap.

Purchase/Order/stock/audit/outbox effects share one transaction; provider receipts are durable before their business reconciliation. Local Phase 04 C04 adds `MixedCheckoutHoldCreated`, `MixedCheckoutHoldReleased`, `MixedCheckoutHoldExpired`: aggregate version 1 on creation, 2 on terminal transition, separately scoped to owning Customer and each affected Vendor workspace. Local Phase 04 C05 emits `MixedPaymentRequested`, `MixedPaymentResultRecorded`, `MixedPaymentChanged`, `MixedRefundRequested`, `MixedRefundCompleted` only in the authoritative Customer workspace, with opaque payment/hold/refund IDs, state and explicit sandbox marker. Request/attempt, receipt/outbox, capture/state/audit/outbox and refund/reversal/state/audit/outbox each commit together. Replays/duplicates and competing workers create no repeated monetary event. No private Staff, signing secret or provider payload is published.
